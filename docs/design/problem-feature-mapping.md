# 사업 런칭 여정 기준 문제 체계 (MECE)

병목: 아이디어에서 기술적으로 구체화된 사업 아이템으로 넘어가는 과정의 **지식 장벽**.

## 1. 기준: 두 축

**축 1 · 사업 단계 (시간 흐름)**: 특허 기반 사업을 런칭할 때 순서대로 거치는 네 단계.

1. 탐색: 내 아이디어가 기존 기술 지형의 어디에 있는지 본다.
2. 검증: 가까운 특허와 나의 차이를 확인한다.
3. 리스크: 같은 분야에서 있었던 분쟁과 위험 정도를 본다.
4. 포지셔닝: 비어 있는 영역을 찾아 방향을 정한다.

런칭 이후의 모니터링은 이 체계에서 뺀다. 필요하면 다음 단계로 따로 정한다.

**축 2 · 판단 대상 (무엇을 보는가)**: 다섯 가지로 나눈다. 한 기능은 대상 하나에만 속한다.

- 지형: 기존 특허 전체의 분포
- 아이디어: 사용자가 입력한 아이디어
- 개별 특허: 특허 한 건의 내용
- 사례: 과거 분쟁 사례
- 지표: 지형과 사례를 합친 계산 값

## 2. 기능 배치 (단계 × 대상)

| 단계 \ 대상 | 지형 | 아이디어 | 개별 특허 | 사례 | 지표 |
|---|---|---|---|---|---|
| 탐색 | F1 지형 보기 | F2 아이디어 위치 찾기 | | | |
| 검증 | | | F3 요소 비교 | | |
| 리스크 | | | | F4 사례 연결 | F5 위험 지표 |
| 포지셔닝 | F6 빈 영역 추천 | | | | |

셀이 비어 있으면 해당 단계에서 그 대상을 다루지 않는다는 뜻이다.

## 3. 사업가가 겪는 문제 (기능별)

| 문제 | 해당 기능 | 해커톤 상태 |
|---|---|---|
| Q1. 기존에 무엇이 있는지 모른다 | F1 지형 보기 | 구현 (기본 지도) |
| Q2. 내 아이디어가 어디 있는지 모른다 | F2 아이디어 위치 찾기 | 구현 (검색, 특허번호·회사명 조회) |
| Q3. 남과 무엇이 같고 다른지 모른다 | F3 요소 비교 | 구현 |
| Q4. 과거 분쟁이 있었는지 모른다 | F4 사례 연결 | 구현 (정적 31건) |
| Q5. 얼마나 위험한지 모른다 | F5 위험 지표 | 밀집도 구현, 계산식 보류 |
| Q6. 어디에 기회가 있는지 모른다 | F6 빈 영역 추천 | 보류 |

## 4. 공통 계층 (단계와 무관하게 모든 기능이 쓰는 것)

- **입력 해석**: 문장 → 검색어, 특허번호 → 특정 특허, 회사명 → 출원인 검색. 입력 방식만 다르고 판단은 하지 않는다.
- **범위 설정 (주제 세션)**: 전체 지형 중 CPC로 좁힌 부분. 모든 단계의 대상 범위를 정한다.

이 두 계층은 기능이 아니라 범위와 입력을 정하므로, 기능 배치표에 넣지 않는다.

## 5. 검토 결과 (MECE 확인)

- 단계: 탐색, 검증, 리스크, 포지셔닝은 시간순으로 겹치지 않는다. 런칭 이후는 범위 밖으로 명시했다.
- 대상: 다섯 대상은 서로 겹치지 않는다. 지표는 지형과 사례를 합친 파생 값이므로 별도 대상으로 둔다.
- 문제: Q1~Q6은 F1~F6과 일대일로 대응한다.
- 이전 유형(A~D)은 "찾기"처럼 두 문제를 묶었는데, 단계와 대상으로 나누자 "찾기"가 탐색(아이디어)과 지형으로 갈라져 이 체계로 대체한다.

## 6. 열린 질문

- F6 빈 영역 추천은 해커톤에 넣을지, 목록(이웃이 적은 영역)만 보여 줄지.
- F5 위험 지표의 계산식은 실험 결과로 정한다. 실험 전에는 밀집도만 보여 준다.
- 단계별 전후 비교 기준은 단계마다 따로 정할지, 전체를 한 번에 볼지.
