# 사업 단계별 기능 명세 (구현 완료 범위)

기준: `problem-feature-mapping.md`의 4단계(탐색, 검증, 리스크, 포지셔닝)와 대상 체계. 화면은 지도 위 **단계 탭**에서 전환한다.

| 단계 | 기능 | 화면 구성 | 데이터 | 구현 |
|---|---|---|---|---|
| 탐색 | 지형 요약 | 총 건수, 상태별 개수, 많은 분야 (누르면 주제 세션), 출원 연도별 추이 | 현재 지도(세션 포함) 점 | 완료 |
| 탐색 | 내 아이디어 위치 | "위치 계산" 버튼 → 지도에 "내 아이디어" 표시, 가까운 특허 5건 | `/api/locate`, 샘플 벡터 | 완료 (샘플 데이터만) |
| 검증 | 용어 비교 | 선택한 특허와 아이디어의 공통 용어, 특허에서 확인되지 않은 용어 | 선택한 특허 텍스트 | 완료 (단어 기준) |
| 리스크 | 밀집도 | 위치 또는 선택 특허 주변 반경 안 특허 수 | 지도 점 | 완료 |
| 리스크 | 연결 사례 | 검색 결과 특허와 키워드 2개 이상 겹치는 사례 수와 목록 | 검색 결과, `cases.ts` | 완료 |
| 포지셔닝 | 빈 자리 | 특허가 없고 주변에 특허가 있는 칸 5곳, 주변 특허 3건씩 | 지도 점, 내 위치 (있으면) | 완료 |

## 설계 원칙

1. **합산 위험 점수는 보여 주지 않는다.** 밀집도와 사례 수를 따로 보인다. 계산식은 실험 결과가 나올 때까지 확정하지 않는다.
2. **판단 대신 근거를 준다.** 용어 비교는 "확인되지 않음"으로 끝내고, 빈 자리는 "기회의 후보"라고 표시한다.
3. **계산 함수는 한 곳에 둔다.** `src/lib/phaseFeatures.ts`가 화면과 테스트가 함께 쓰는 순수 계산이다.

## 알려진 한계

- 위치 계산은 샘플 데이터셋에서만 된다. 한국 데이터는 벡터 저장 방식이 달라 다음 단계에서 지원한다.
- 용어 비교는 단어 기준이라 동의어나 다른 표현은 잡지 못한다. AI 비교는 기존 검색 탭의 "비교"를 쓴다.
- 빈 자리 계산은 지도 격자 기준이라, 지도 크기가 달라져도 결과는 같지만 격자 해상도(20 칸)는 고정되어 있다.
- 목업 모드에서는 위치 계산이 실제 임베딩 대신 샘플 앞쪽 특허를 쓴다.

## 다음 단계

- 한국 데이터의 위치 계산 지원 (벡터를 특허별로 모으는 방식 확정 필요)
- 패널 레이아웃 정리: 지금은 지도 위에 세로로 길게 쌓여 지도를 많이 가린다
- 계산식 실험 결과가 나오면 위험 점수 표시 여부 결정

## 변경 기록 (세션 구조 개정)

- 단계는 3개다: 탐색(지형 보기, 아이디어 위치 찾기, 빈 자리 찾기), 검증(요소 비교), 리스크(연결 사례, 주변 밀집도). 포지셔닝은 탐색에 합쳤다.
- 홈은 지도 중심이다. 지도 위에 "오늘의 랜덤 특허 뽑기" 버튼이 있고, 누를 때마다 전체 특허 중 무작위 한 건을 고른다.
- 입력창에 문장을 보내거나 기능을 고르면 새 대화(세션)가 열린다. 세션 목록은 왼쪽 대시보드에 쌓인다. 현황 대시보드는 두지 않는다.
- 세션은 마스터 DB를 보는 조회 조건이다. 상태 필터, 분야(하위 분류), 정렬(출원 최신순·오래된순·유사도순), 개수(50건·200건·전체)를 가진다. 기본값은 최신 출원 200건이다.
- 유사도순은 검색 점수가 있을 때만 선택할 수 있다.
