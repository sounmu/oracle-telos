# Telos 해커톤 MVP 목표

작성일: 2026-10-16
상태: 이번 해커톤의 목표 범위. 구현 완료 목록이 아니다.
장기 방향: [최종 서비스 목표](product-goals.md)

## 1. 한 문장 목표

내 기술을 입력하면 관련 국내 특허를 찾아 기술 요소별로 비교하고, 기술적으로 가까운 정도를 귀여운 온도로 보여준다.

해커톤은 **찾기 + 비교 + 온도 표시**에 집중한다. 논문·분쟁 분석·법적 위험도 평가는 제외한다.

## 2. 대상과 도메인

- 대상: 자기 기술과 비슷한 특허를 빠르게 확인하려는 스타트업 연구자·개발자·창업자.
- 도메인: 바이오·의료미용 안에서 팀이 설명할 수 있는 한 분야로 제한한다.
- 세부 분야는 관련 특허 확보 가능성과 팀의 이해도를 확인해 선택한다. 아직 확정하지 않았다.
- 데이터: 국내 KIPRIS 특허. 한국 데이터가 없을 때 미국 샘플로 대체하지 않는다.

## 3. 단일 사용자 흐름

1. 기술 설명을 입력하거나 예시 아이디어 3개 중 하나를 선택한다.
2. 검색 진행 상태를 확인한다.
3. 관련 특허 5~10건과 기술 근접도 표시를 본다. 가장 가까운 3건을 먼저 살펴본다.
4. 특허 하나를 선택해 내 기술과 공통점·차이점·추가 확인 사항을 비교한다.
5. 근거가 된 초록·청구항 일부와 원문 링크를 확인한다.

기존 지도에서는 검색 결과를 하이라이트하고 점을 클릭하면 같은 상세·비교 흐름으로 연결한다.

## 4. 구현 범위

| 기능 | 이번 구현 범위 |
|---|---|
| 입력 | 자연어 기술 설명 하나, 예시 버튼 3개 |
| 검색 | 기술 요소·동의어 추출, 여러 검색 조건으로 KIPRIS 후보 조회 |
| 후보 선별 | 출원번호 중복 제거, 제목·초록 기반 의미 유사도 정렬 |
| 상세 조회 | 선별한 상위 후보의 상세·청구항 조회 |
| 결과 | 제목, 출원인, 상태, 관련 이유 한 줄, 근접도 |
| 비교 | 기술 요소별 내 기술·상대 특허·공통점 또는 차이·추가 확인 사항 |
| 온도 | 3단계와 귀여운 캐릭터 표정, 단계별 근거 |
| 지도 | 기존 지도 활용, 검색 결과 하이라이트와 상세 연결 |
| 근거 | 비교에 사용한 원문 일부와 출처 링크 |
| 예외 처리 | 결과 없음, 자료 부족, 인증·한도·네트워크 오류 안내 |

## 5. 검색 설계

`기술 설명 → 검색어 묶음 생성 → KIPRIS 후보 검색 → 중복 제거 → 의미 유사도 정렬 → 상위 후보 상세 조회 → 비교`

- 넓은 검색어 하나로 최신 100건만 가져오는 방식에서 발전시킨다.
- 기술 요소를 여러 묶음으로 검색한다. 모든 요소를 동시에 필수 조건으로 강제하지 않는다.
- API가 지원하는 자유검색·발명명칭·초록·청구범위 필드를 검토해 활용한다.
- 각 검색의 후보는 출원일 최신순으로 수집할 수 있지만 최종 목록은 사용자 기술과의 관련도로 정렬한다.
- 검색 목록의 제목·초록으로 먼저 선별해 불필요한 상세 조회를 줄인다.
- 관련도는 확보한 후보 안에서의 순위다. 국내 전체 특허에 대한 포괄적 검색을 주장하지 않는다.
- 예시 3개는 사전 수집한 결과를 캐시한다. 새 입력도 같은 검색·선별 절차로 처리한다.
- 호출량·후보 수·상세 조회 수의 상한은 실제 응답 속도와 이용 한도를 확인해 정한다.

## 6. 비교 화면

긴 설명보다 기술 요소별 표를 우선한다.

| 기술 요소 | 내 기술 | 찾은 특허 | 비교와 근거 |
|---|---|---|---|
| 요소 A | 사용자 입력에서 확인한 내용 | 원문에서 확인한 내용 | 공통점 또는 차이, 근거 문단 |
| 요소 B | 입력에 없는 경우 미기재 | 원문에서 못 찾은 경우 확인되지 않음 | 추가 확인할 질문 |

- 사용자 입력에 없는 기능을 만들어 넣지 않는다.
- 가져온 원문에서 찾지 못한 요소는 ‘없음’ 대신 ‘확인되지 않음’으로 표시한다.
- 일부 청구항만 제공했다면 전체 청구항을 검토한 것으로 표현하지 않는다.
- 기술적 공통점을 권리 침해나 특허 등록 가능성으로 단정하지 않는다.

## 7. 온도 표시

표시 이름은 **기술 근접도**, 설명은 ‘내 기술과 얼마나 가까울까요?’로 한다. 법적 위험도나 침해 확률이 아니다.

| 단계 | 문구 예시 | 표현 |
|---|---|---|
| 서늘 | 다른 점이 많아요 | 차분한 표정 |
| 따뜻 | 겹치는 기술 요소가 있어요 | 관심 있는 표정 |
| 뜨거움 | 가까운 요소가 많아요. 자세히 비교해 봐요 | 놀란 표정 |
| 자료 부족 | 비교할 근거가 부족해요 | 별도 중립 상태 |

- 각 단계에는 겹치는 기술 요소를 설명하는 짧은 근거를 붙인다.
- 소수점 온도·퍼센트는 이번 범위에서 제외한다.
- 임베딩 점수를 그대로 온도로 변환하지 않는다. 단계 기준은 데모 예시와 비교 근거를 바탕으로 정하고 일관되게 적용한다.
- 후보가 없거나 자료가 부족하면 낮은 온도로 표시하지 않는다.
- 특허의 등록·거절·심사 중·상태 미확인 색상과 온도 표현을 구분해 혼동을 막는다.

## 8. 제외 범위

- 논문 검색·연결.
- 분쟁 사례 화면, 판결·심결 분석, 심판 이력.
- 법적 위험도 점수와 침해 확률.
- 출원인·발명자 네트워크와 인력 이동 분석.
- 회사명·특허번호 전용 입력 흐름, 카테고리 탐색, IR·제품 소개서 업로드.
- 별도의 기술 확장 추천 목록.
- 지도 분류 방식 추가와 대규모 시각화 개편.
- 회원가입·결제·구독 관리.
- 해외 데이터 확대.

## 9. 기존 구현과 추가 작업

현재 프로젝트에는 국내 특허 수집·색인, 저장 데이터 검색, 지도·상세, AI 응답 흐름이 있다. KIPRIS 수집 스크립트는 출원일 최신순 기본 최대 100건으로 변경했다.

추가 작업의 중심은 사용자 입력을 KIPRIS 후보 검색과 연결하고, 수집 전후에 관련도 선별을 적용하는 것이다. 기술 요소별 비교와 근거 연결, 온도 표시도 이번 목표에 맞춰 구현·검증해야 한다. 기존 화면이 있다는 것만으로 목표가 완료된 것은 아니다.

## 10. 구현 우선순위와 완료 기준

우선순위: **검색 품질 → 근거 있는 비교 → 온도 표시 → 기존 지도 연결 및 시각적 마무리**.

- [ ] 팀이 설명할 수 있는 세부 도메인과 예시 3개를 확정한다.
- [ ] 예시마다 기술적으로 관련된 특허가 검색되고 관련 이유를 설명할 수 있다.
- [ ] 새 기술 설명도 후보 검색부터 비교까지 이어진다.
- [ ] 선택한 특허와 기술 요소별 비교가 표시된다.
- [ ] 비교 근거를 원문 일부와 출처 링크로 확인할 수 있다.
- [ ] 온도 단계와 그 이유가 일치하며 법적 위험도로 표현되지 않는다.
- [ ] 검색 결과 없음·자료 부족·API 오류를 구분해 안내한다.
- [ ] 지도 하이라이트와 클릭 상세가 검색 결과와 연결된다.
- [ ] 데이터가 없어도 앱이 실행되고 준비 방법을 안내한다.
- [ ] 한국 수집물과 API 키를 공개 정적 파일이나 Git에 포함하지 않는다.

데모 성공 기준은 사용자가 ‘내 기술과 어떤 점이 비슷하고 다른지’를 이해하고, 그 설명의 근거를 직접 확인하는 것이다.
