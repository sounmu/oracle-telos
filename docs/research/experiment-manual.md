# 위험도 계산식 실험 매뉴얼 (인수인계용)

상태: **판단 보류**. 계산식을 고르기 위한 실험은 설계와 스크립트까지 완료했지만, 분쟁 사례와 연결되는 특허 데이터가 부족해 결과를 낼 수 없었다.

## 1. 목적

분쟁 위험도 배경을 계산하는 방식 5가지(F1~F5) 중 무엇을 쓸지, 반경(24/48/96px)과 키워드 기준(2개/3개 이상)을 함께 바꿔 30조건을 비교하고 채택 기준을 정한다.

## 2. 현재까지 확인된 사실

| 확인 항목 | 결과 |
|---|---|
| 샘플 지도(미국 2016.01, 3,000건)와 분쟁 사례 24건의 키워드 연결 | 0건 (키워드 2개 이상 기준) |
| 전체 HUPD 샘플(26,808건) 스캔 | 연결 4건. 그중 3건은 주제와 무관(마이크로유체, HIFU) |
| 예측 타당성 계산 가능 여부 | 불가. 사례가 하나도 연결되지 않아 계산할 대상이 없음 |
| 실험 실행 결과 | 보고서는 생성됨. "판단 보류" 표시 있음 |

원인: 분쟁 사례 24건은 바이오·의료 분야(예: 보툴리눔 톡신, GLP-1 미립구, 구강스캐너)인데, 샘플 특허는 2016년 1월 출원 무작위 표본이라 해당 분야가 거의 없다.

## 3. 실행 준비

- 저장소: `oracle-telos`, 브랜치 `feat/case-embedding` (커밋되지 않은 변경이 있음)
- 설치: `pnpm install`
- 외부 키: 이 실험의 1~2단계는 키가 필요 없다. 3단계에서 KIPRIS를 쓸 때만 `.env`에 `KIPRIS_API_KEY`가 필요하다.
- 호출 한도: KIPRIS Plus는 계정마다 한도가 있다. 호출 전에 남은 횟수를 확인한다.

## 4. 실행 순서

### 1단계: 현재 상태 재현 (호출 없음)

```bash
pnpm exec tsx scripts/experiments/risk-formula-experiment.ts
```

- 결과: `docs/research/risk-experiment-report.html`
- 상단에 "판단 보류" 안내가 있으면 정상이다.

### 2단계: 연결되는 특허 데이터 확보 (먼저 방법을 정한다)

아래 두 방법 중 하나를 고른다. 어느 쪽이든 결정 전에 계정주와 호출 여부를 확인한다.

- **A. KIPRIS 검색 (호출 필요)**: 사례마다 핵심 키워드 2~3개로 `getAdvancedSearch`를 호출해 후보를 받는다. 필요한 특허만 서지상세를 받는다. 사례당 1~3회 검색을 목표로 하고, 전체 호출 수는 약 24~72회다. 결과는 `.cache/`에 저장해 재호출을 피한다.
- **B. 다른 공개 데이터 (호출 없음 또는 별도 확인)**: 전체 HUPD 명세를 쓰되 키워드를 본문 전체로 넓힌다. 다만 4건 수준이라 효과가 작을 것으로 예상된다.

### 3단계: 연결 수 확인

- 목표: 키워드 2개 이상 기준으로 사례 **최소 8건 이상**이 특허와 연결될 것.
- 8건 미만이면 4단계로 가지 말고 2단계를 다시 한다.

### 4단계: 실험 실행과 판단

1. 수집한 특허를 `public/data/patents.json`과 같은 형식(좌표 포함)으로 만든다. 좌표는 MiniLM 임베딩 후 UMAP으로 계산한다. 이 과정은 `pnpm build:data`의 방식을 참고한다.
2. 위 스크립트를 다시 실행한다.
3. 채택 규칙은 `docs/research/experiment-plan.md` 6장을 따른다.
   - 표시 범위 5~40% 조건만 남긴다.
   - 예측 타당성과 안정성의 순위 평균이 가장 좋은 조건을 고른다.
   - 두 지표 구간이 겹치면 현재 식(F3)을 유지한다.
4. 사람 평가(전문가 일치)는 두 명이 영역 20곳을 블라인드로 평가한다. 이 부분은 자동화되지 않는다.

### 5단계: 기록

- 보고서를 다시 만든다.
- 아래 의사결정 아카이브 표에 행을 추가한다.

## 5. 알아야 할 함정

- `public/data/patents.json`의 초록은 300자로 잘려 있다. 키워드 매칭이 빠질 수 있으므로, 실험에는 전체 초록을 쓰는 것이 낫다.
- 사례 키워드는 한국어와 영어가 섞여 있다. 영문 특허에는 한국어 키워드가 절대 맞지 않는다.
- 예측 타당성 계산에서 사례 하나를 빼면 연결 수가 줄어든다. 연결이 적으면 결과가 불안정하다.
- 반경을 늘리면 모든 셀이 붉어져서 표시 범위가 커진다. 표시 범위 기준을 같이 봐야 한다.
- 보고서 생성 스크립트는 사례 연결이 0건이면 순위를 계산하지 않고 "판단 보류"로 표시한다.
