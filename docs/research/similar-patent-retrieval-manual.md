# 분쟁 사례와 비슷한 특허 호출 매뉴얼

상태: **작성 완료, 호출은 아직 실행하지 않음.** 실행에는 계정주의 KIPRIS 키와 승인이 필요하다.

## 1. 기준 데이터

- 분쟁 사례: `src/lib/cases.ts` (24건, 바이오·의료 분야)
- 사례마다 쓸 수 있는 필드
  - `tech`: 기술 쟁점 한 줄 (검색 문장의 중심)
  - `keywords`: 검색어 묶음 (한국어·영어 혼합)
  - `ids.patents`: 사례에 나온 특허번호 (대부분 미국·유럽 번호, 한국 출원번호와 직접 연결되지 않음)
  - `sources`: 판결문·심결문·공시 출처 URL
- 판결문 원문 파일은 로컬에 없다. 확인한 결과 `Downloads`에 관련 없는 공모전 신청서 1건뿐이다.

## 2. 호출 절차 (계정주가 실행)

1. **검색어 만들기**: 사례마다 `keywords` 중 한국어 2~3개와 영어 1~2개를 골라 짧은 검색어 묶음을 만든다. 긴 문장은 KIPRIS 키워드 검색에 맞지 않는다.
2. **KIPRIS 후보 검색**: `getAdvancedSearch`에 검색어를 넣어 사례당 1~3회 호출한다. 한 번에 최대 20건을 받는다. 출원일 최신순 기본 정렬을 쓴다.
3. **후보 선별**: 후보의 제목·초록을 `tech`와 비교해 가까운 순으로 정렬한다. 상위 5건 정도만 상세 조회한다.
4. **상세 조회**: `getBibliographyDetailInfoSearch`로 서지·초록·청구항·출원인을 받는다. 호출 1건당 2회(서지 + CPC)가 든다.
5. **저장**: 결과는 `.cache/` 아래에 검색어와 함께 저장해서 같은 검색을 반복하지 않는다.
6. **사례 연결**: 받은 특허가 사례의 키워드와 2개 이상 겹치는지 확인하고, 연결 목록을 사례 id와 함께 기록한다.

## 3. 호출 예산

- 사례 24건 × 검색 1~3회 = 약 24~72회
- 상세 조회: 사례당 최대 5건 × 2회 = 최대 240회. 실제로는 중복 제거 후 훨씬 적다.
- 실행 전에 계정의 남은 호출 횟수를 확인한다.

## 4. 끝난 뒤 확인할 것

- 사례마다 연결된 특허 수 (0건인 사례는 표시)
- 연결된 특허의 상태(승인·거절·심사중)와 CPC가 사례의 분야와 맞는지
- 한국 특허는 미국 샘플과 점 공간이 달라서, 지도에 올리려면 별도 임베딩과 좌표 계산이 필요하다.

## 5. 공개 판례 추가 (별도 작업)

- 사례 카드와 같은 형식(`DisputeCase`)으로 몇 건만 추가한다.
- 각 사례의 판결 사실, 날짜, 사건번호, 출처 URL은 원문에서 확인한 뒤 넣는다. 확인하지 못한 내용은 비워 두고 "확인되지 않음"으로 표시한다.
- 이 작업은 아직 시작하지 않았다.
