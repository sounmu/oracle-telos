# 기술 유사성·관계선 기준 실험 계획

## 1. 질문

지도 거리와 관계선이 "같은 기술 영역"을 얼마나 잘 나타내는가? 어떤 텍스트 필드, 임베딩, 유사도 정의, 관계선 규칙의 조합이 가장 나은가?

## 2. 조건 (요인)

| 요인 | 수준 |
|---|---|
| A. 텍스트 필드 | (a) 제목, (b) 제목+초록, (c) 제목+초록+첫 청구항 |
| B. 임베딩 | (1) 현재 다국어 MiniLM, (2) PatentSBERTa(영문 특허 전용), (3) TF-IDF 기준선 |
| C. 유사도 정의 | (i) 임베딩 코사인, (ii) CPC 하위 분류 공유 여부, (iii) CPC 그룹 Jaccard, (iv) (i)과 (ii)의 결합 |
| D. 관계선 규칙 | (α) 지도상 가까운 이웃 2개(현재 구현), (β) 같은 분류 중 무작위 2개, (γ) 같은 분류 중 임베딩 상위 2개, (δ) 임계값 이상만 |
| E. 데이터 언어 | 영문 샘플, 한국 KIPRIS(가능한 범위) |

전 조합은 많으므로 A×B는 (b)와 (c)만, C와 D는 전부 돌린다. 조합 수는 약 2×3×4×4 = 96이다.

## 3. 정답(평가 기준)

정답 라벨은 없다. 세 가지를 함께 쓴다.

1. 전문가 평가: 질의 특허 30건을 고르고, 각 질의마다 후보 상위 10건을 0(무관), 1(부분 관련), 2(같은 기술 영역) 세 단계로 두 명이 독립 평가한다. 두 사람의 일치도(Cohen's kappa)를 함께 보고한다.
2. CPC 보조 정답: 하위 분류 공유를 약한 정답으로 쓴다. 임베딩 조건의 유효성 검증용이며, CPC 조건 자체를 평가할 때는 사용하지 않는다(순환 방지).
3. 분쟁 사례 연결: 24건 사례와 연결되는 특허 묶음을 약한 정답으로 쓴다.

## 4. 지표

- 검색 품질: nDCG@10 (전문가 평가), Precision@10 (CPC 보조 정답)
- 관계선 품질: 같은 하위 분류로 연결된 간선 비율(homophily), 평균 연결 수, 고립 노드 비율, 연결 성분 수
- 가독성: 지도에서 이웃 5개를 보여 주고 "같은 기술처럼 보이는가"를 1~5점으로 평가 (사용자 2~3명)

## 5. 절차

1. 질의 30건과 후보 풀을 고정한다. 무작위 시드는 42로 고정한다.
2. 조건별로 검색과 관계선을 만든다.
3. 전문가 평가 표를 채운다. 평가자는 조건 이름을 모르게 한다(블라인드).
4. 지표를 계산하고 부트스트랩 95% 구간(1,000회)을 함께 낸다.

## 6. 사전 결정 규칙

- 1순위: nDCG@10이 가장 높은 조건.
- 제약: 평균 연결 수 2 이하, 고립 노드 비율 30% 이하.
- 둘 중 하나라도 어기면 다음 후보로 넘어간다.
- 구간이 겹치면 단순한 조건(현재 구현, 임베딩 코사인, 관계선 α)을 유지한다.

## 7. 해커톤 범위에서 가능한 축소안 (약 2시간)

- 질의 10건, 조건 A(b)와 B(1)만, C(i)·(ii)·(iv), D(α)·(γ). 조건 수 6개.
- 평가자 2명, 질의당 후보 10건.
- 결과는 "현재 구현이 충분한가"에 답하는 수준으로만 보고한다.

## 8. 한계

- 전문가 평가는 소규모이며 특정 도메인(바이오·의료)에 치우칠 수 있다.
- 영문 특허 전용 모델(PatentSBERTa)과 한국어 사례는 같은 조건으로 비교할 수 없다. 언어별로 따로 보고한다.
- 정답이 임베딩 학습에 쓰인 CPC라면 순환이 생긴다. 4장 3번 기준으로 구분해 해석한다.
